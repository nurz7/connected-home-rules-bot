# Connected Home Rules Bot

Тестовый Telegram-бот, который помогает сотрудникам находить ответы в документе
«Правила компании». Проект выполнен как тестовое задание для Connected Home.
Все правила и суммы взяты из тестового документа задания.

Бот отвечает кратко и по-русски, указывает пункты документа и объясняет,
какой именно информации в правилах нет.

## Возможности

- Ответы по 10 разделам: график, удалённая работа, отпуск, больничный,
  зарплата, офис и пропуск, IT-помощь, командировки, обучение, дресс-код.
- Обработка нескольких вопросов в одном сообщении.
- Контекст для уточняющих вопросов: последние три пары «вопрос — ответ»
  отдельно для каждого личного чата.
- Ссылки на пункты правил сразу под ответом.
- Уточнение неизвестной части вопроса и направление в HR.
- Кнопка «Связаться с HR», открывающая
  [страницу контактов Connected Home](https://connectedhome.kz/ru/new-contact).
  Это общие контакты компании.
- Журнал вопросов, на которые не удалось ответить полностью.
- Отдельное сообщение при недоступности AI API.

## Примеры диалога

**Вопрос:** Сколько дней ежегодного отпуска?

> Ежегодный оплачиваемый отпуск — 24 календарных дня.  
> (Пункт 3 правил)

**Уточнение:** А за сколько подавать заявление?

> Заявление подаётся в HR не позднее чем за 14 дней до начала отпуска.  
> (Пункт 3 правил)

**Вопрос:** Можно носить шорты в офисе?

> Дресс-код: свободный, но опрятный.  
> (Пункт 10 правил)
>
> В правилах не указано, разрешено ли носить шорты в офисе. Обратитесь в HR.

Это примеры ожидаемого поведения. Формулировка неизвестной части зависит
от вопроса и ответа модели; факты из правил подставляет Python.

## Как устроен бот

1. `bot.py` получает сообщения из личных чатов Telegram через polling.
2. `rules_ai.py` передаёт Gemini вопрос, короткую историю и полный текст правил.
   Документ небольшой, поэтому отдельный поиск по фрагментам не используется.
3. Gemini возвращает JSON: номера подходящих фрагментов (`clauses`) и
   конкретные вопросы, для которых не хватает информации (`missing_details`).
4. Если модель предполагает пробел, второй запрос перепроверяет его по документу.
   Сроки, лимиты и условия могут отвечать на вопрос без отдельного пункта,
   дословно повторяющего формулировку сотрудника.
5. Python проверяет формат и номера фрагментов, собирает ответ из текста правил
   и добавляет ссылку на пункты. Для неизвестных частей формирует пояснение про HR.

Например, срок подачи заявки за один день отвечает на вопрос о подаче на сегодня.
При этом общий дресс-код не определяет допустимость ношения конкретной одежды.
Выбор пунктов и оценка полноты ответа зависят от модели.

## Команды

| Команда | Действие |
| --- | --- |
| `/start` | Приветствие, кнопка контактов и очистка контекста |
| `/reset` | Очистка контекста текущего чата |
| `/hr` | Кнопка перехода на страницу контактов компании |

## Файлы проекта

| Файл | Назначение |
| --- | --- |
| `bot.py` | Telegram-обработчики, история, кнопка контактов и журнал |
| `rules_ai.py` | Инструкция модели, Gemini API, проверка и сборка ответа |
| `rules.txt` | Тестовый документ с правилами |
| `tests/test_bot.py` | Автоматические проверки с имитацией Telegram и Gemini |
| `requirements.txt` | Зависимости Python с закреплёнными версиями |
| `.env.example` | Шаблон конфигурации без токенов и API-ключей |
| `.gitignore` | Исключения для локальных настроек, журналов и служебных файлов |

## Технологии и конфигурация

Python 3.11+, python-telegram-bot, httpx, python-dotenv, Gemini API.

Ключи Telegram и Gemini читаются из переменных окружения или локального `.env`.
В репозитории публикуется только `.env.example` с пустыми полями ключей.
Модель задаётся через `GEMINI_MODEL`, ссылка контактов — через `HR_URL`.

Память диалога хранится в оперативной памяти и очищается при перезапуске.
Журнал `unanswered.jsonl` содержит время в UTC и текст вопроса, без имени и ID
пользователя. Журнал не входит в репозиторий.

## Проверка качества

Автоматические тесты проверяют сборку ответа из документа, обработку неизвестных
частей, повторную проверку предполагаемых пробелов, ошибки API, память,
разделение чатов, журнал и кнопку контактов.

В тестах используются имитации обоих API, настоящие ключи не требуются.
Они проверяют работу кода; понимание формулировок реальной моделью проверяется
отдельно в Telegram.

Для демонстрации бот запускается локально. Публикация репозитория сама по себе
не запускает Telegram-бота.
